# Inventaire de couverture du code CRUG

Base de comparaison : `git diff --name-only releases/gcc-16.2 c0dcb18d649a909846e8b2bcefe4eb39b1841dc9`. Le périmètre inclut les nouveaux modules CRUG et **les raccords CRUG dans des fichiers GCC hérités**. Cette table dit ce qui a été exécuté/revu dans la présente campagne ; elle ne donne aucune garantie aux zones UNKNOWN. Les preuves de la campagne précédente sont référencées dans `REVALIDATION.md`.

| Famille de code | Fichiers/raccords CRUG | Exécuté ou examiné dans la nouvelle campagne | Reste UNKNOWN |
|---|---|---|---|
| Ownership, borrow, destruction | `gcc/c/crug-ownership.cc` et `.h` ; raccords `gcc/c/c-decl.cc`, `c-parser.cc`, `c-tree.h` | F-01 et ses contrôles strict/hybride, O0/O2/O3/LTO, Valgrind/LSan ; K-002/K-016–020 rejoués ; 160 fuzz CRUG | CFG entier, agrégats imbriqués, goto, preuve `restrict` exhaustive, toutes conversions |
| Types sûrs et grammaire | `gcc/c/crug-safe.cc`/`.h` ; `c-parser.cc`, `c-decl.cc` | Rejeu diagnostics strict/raw, match/slice sélectionnés ; fuzz avec expressions imbriquées | Tailles/alignements extrêmes de chaque type, ensemble DejaGNU |
| Captures, tâches et Send/Sync frontend | `gcc/c/crug-send-sync.cc`/`.h`, `crug-tasks.cc`/`.h` ; raccords parseur/déclarations | Rejeu Send/Sync et programmes runtime/scopes compilés ; cycles et spawns externes | Graphes de captures complexes, autres ABI, toutes frontières d'appel |
| Channels/select frontend | `gcc/c/crug-chan.cc`/`.h` ; raccords `c-parser.cc` | C-01 alignement, select répété O0/O2/O3 ; K-009/K-010 diagnostics | Transfert owning dynamique, tous close/select concurrents |
| Métadonnées et diagnostics | `gcc/c-family/crug-ffi.cc`/`.h`, `crug-common.cc`/`.h`, `crug-diagnostics.cc`/`.h` ; `c-cppbuiltin.cc`, `c-opts.cc`, `c.opt`, `common.opt` | 9 sidecars ciblés, 30 fuzz, conflit/symlink/limites ; K-021–023 et diagnostics historiques ; F-02–F-04 | Toutes combinaisons de flags, callbacks, signatures atypiques, diagnostics SARIF complets |
| Build et intégration GCC | `gcc/c/Make-lang.in`, `gcc/crugc` et raccords d'options ci-dessus | Identité du `cc1`/`xgcc`, 20 diagnostics sélectionnés, `sh -n gcc/crugc`, revue du lanceur historique | Installation sous préfixes arbitraires, build GCC intégral de cette seconde campagne |

| Migration et outillage | `c2crug`, `scripts/test-c2crug.py`, `validate-c2crug-report.py`, `gate.sh`, `check-gate-archives.sh`, `check-ci-gate.sh`, `package.sh` ; autres `scripts/check-*.sh` | 73 tests migration, macro/sidecar/ressources ; gate/archives/CI auto-tests ; syntaxe `package.sh` | Package installé, ensemble des autres checks release, chemins de lanceur atypiques |
| Benchmarks et CI | `bench/channels/chanbench.c`, `bench/concurrency/*`, `.github/workflows/*` | `chanbench` reconstruit avec SHA ; mesures caches séparés ; CI gate auto-test | Autres benches, exécution des workflows GitHub et performance machine native |

Les documents `spec/` et `docs/crug/adr/` fournissent les contrats et la hiérarchie ; ils ne remplacent pas les oracles d'exécution. Le delta GCC hérité a été ciblé sur les ajouts CRUG. Aucun audit général de GCC amont, de ses bibliothèques ou de l'ensemble de ses tests n'est revendiqué.
